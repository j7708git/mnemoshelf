## v0.9.2 重點

記憶管理改為對完整資料庫篩選後分頁，原文以整個回合顯示。專案、寫入者與內容條件採一致的
AND 比對，下拉選單來自完整記憶庫；語意召回預覽與管理清單各自使用自己的條件。

- 來源專案、整理歸屬與召回用途分開保存。改成跨專案使用不會清掉專案資訊；停用召回的內容
  仍可在管理頁查看。
- 召回規則支援專案、寫入者及兩者組合，預設只影響之後寫入。明選套用既有資料時先預覽
  變更數，保留單筆例外；資料或規則已變動時要求重新預覽。
- 新增 Codex Stop 可見原文保存、Antigravity Adapter、共用 Hook 核心及通用 Hook CLI。
  Hook 與 MCP 可並用，接入設定需由使用者自行啟用。
- 搜尋、原文續讀、外掛與 Hook 使用一致的召回用途；新增 v3 備份以保存組織快照與規則，
  仍支援匯入 v1／v2。

## 升級與回滾

1. 升級前先完全結束服務並備份資料目錄；PostgreSQL 使用者先建立資料庫備份。
2. 首次啟動會套用資料庫遷移 `0010_memory_organization`。既有內容、ID、向量、釘選、
   版本關係與刪除事件記錄保留；歸屬與用途沿用舊值，最初來源無法確認時保留未知。
3. v3 NDJSON 是內容備份，不含向量、已刪歷史或完整資料庫狀態，也不能匯入舊版 App。
   回滾時須同時換回舊版 App 與升級前資料庫，不要讓舊服務直接寫入升級後的資料庫。
4. 完整使用新召回規則，請同步服務、外掛與 Hook 腳本；更新 App 不會自動切換既有 Hook
   指向的原始碼建置路徑，也不會自動改寫宿主設定。

詳細規則見 [記憶整理與召回規則](https://github.com/j7708git/mnemoshelf/blob/v0.9.2/docs/memory-organization.md)，
備份與還原步驟見 [更新說明](https://github.com/j7708git/mnemoshelf/blob/v0.9.2/docs/updates.md)。

## 已知界線

- 新記憶介面已用 production Web、隔離服務及合成資料操作驗證；資料保留亦以舊 schema
  合成資料庫驗證。這不代表真實模型召回品質或各平台安裝後完整宿主流程均已驗證。
- 本版跨版本 App 內更新流程尚未實機驗證。macOS 持續只檢查並開啟下載頁，不自動安裝；
  macOS 安裝包採 ad-hoc 簽章、未公證，Windows 安裝包未簽章。
- 召回規則是本機單一 owner 的使用偏好；寫入者只是來源標記，不是身分驗證或權限隔離。
